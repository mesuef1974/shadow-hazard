# مهمة 0004: CI عند Pull Request + خلاصة الفشل + الخلاصة الأسبوعية

- الهدف: الطبقة 2 من ADR 0003.
- `.github/workflows/ci.yml`: تُضاف `shz sim` و`shz eval` إلى وظيفة «Pre-push check» القائمة (من 0002) بعد `scripts/prepush_check.py`، ويُرفع `runs/` كأرتفاكت. لا ملف workflow ثانٍ (دمج 2026-11-04).
- `scripts/failure_digest.py`: عند فشل `eval` يكتب `runs/<timestamp>/failure-digest.md` بحد 40 سطرًا: السيناريو، المقياس، الفرق عن خط الأساس، الملفات المتغيرة في آخر إيداع. لا سجلات خام.
- `scripts/weekly_digest.py`: يولّد `docs/digests/weekly-<date>.md`: عدد التشغيلات، اتجاه المقاييس الثلاثة، مهام `docs/tasks/` المفتوحة، سطر الكلفة (يُدخله المشرف يدويًا من `/cost`). يُشغَّل يدويًا كل خميس؛ لا جدول.
- القبول: Pull Request يكسر تأكيدًا في `eval` يظهر أحمر مع ملف الخلاصة في الأرتفاكت؛ الخلاصة الأسبوعية تحت 60 سطرًا.
- خارج النطاق: أي مهمة مجدولة؛ أي محاسبة توكنز في قاعدة البيانات؛ `backend/` خارج `simulation/`.
- المرجع: ADR 0003 الطبقة 2، مهمة 0002 (الحرّاس). لا تقرأ غيرهما.
- الإنهاء: ثلاثة أسطر تحت «حالة الكود» في ملف التسليم.
- الحالة: بعد 0002 و0003.
