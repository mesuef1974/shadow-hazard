# مراقب المهام

## الحالة المعتمدة

المراقب المحلي `run_model_dispatcher --watch` يحول الطلبات إلى سجلات ثابتة في `execution_context.SessionDispatch`، ثم يرسل مهام `workspace-write` إلى الجلسات القائمة عبر Codex App Server الرسمي. لا يستدعي `codex exec` ولا ينشئ محادثة جديدة. إشارة Windows من نموذج الطلب توقظه بعد حفظ المعاملة؛ لا يشغّل نموذجًا دوريًا. عقد الجسر وتسلسل الحالات موثقان في [session-outbox.md](session-outbox.md).

الحالات: `queued → claimed → sent → acknowledged → completed`، أو `uncertain` عند عدم وضوح النتيجة. لا يعاد إرسال الغامض تلقائيًا. المطالبة الذرية تولد claim token فريدًا، ويجب استخدامه لكل انتقال.

Windows Scheduled Task `ShadowDanger-ModelDispatcher` يشغّل العامل الطويل العمر مع تسجيل الدخول، ويحميه قفل نظام التشغيل من النسخ المكررة. يعتمد الاتصال على Codex App Server وملفات حساب Codex المحلية؛ إذا توقف Codex أو صار الدور غير محسوم، لا يعيد العامل المهمة تلقائيًا. سجلات `ModelJob` القديمة تبقى تاريخًا ولا تُحذف.

## التوجيه والاستهلاك

يختار نوع المهمة مالكها بين الجلسات القائمة: البرمجة إلى backend، التصميم إلى frontend، والنص إلى coordination؛ يثبت النموذج والتفكير وسبب التوجيه في سجل الإرسال. نموذج أعلى من Luna يتطلب موافقة تصعيد صريحة.

تحفظ أرقام الاستهلاك فقط إذا وصلت أدلة عينات محددة من جامع الجلسات، ولا تُضاف مرة ثانية فوق إجماليات الجلسة. عند غياب ربط موثوق بمعرف الدور وعينة مصدر، يبقى الاستهلاك غير معروف.

## التاريخ

المشغل السابق استعمل `codex exec` في جلسة مستقلة؛ لم يستأنف محادثة سطح المكتب ولم يغير نموذجها. استُبدل ذلك المسار في 2026-10-31 بجسر App Server إلى `thread_id` القائم بعد فحص حالته. توثيق التجارب التاريخية لا يثبت تنفيذ مهمة؛ يلزم دليل الدور من rollout.
