# موصل تشغيل النماذج المحلي

## الآلية المعتمدة محليًا

يستخدم الموصل `codex exec` لإنشاء تنفيذ مستقل لكل طلب، بالنموذج والتفكير المحددين في السياسة. يرتبط التنفيذ بميثاق الجلسة في قاعدة البيانات وبسجل استهلاك التوكنز. لا يستأنف محادثة سطح المكتب ولا يغير نموذجها ولا يرث تاريخها؛ يرسل نطاق الجلسة وميثاقها والمهمة المحددة فقط، إضافة إلى السياق الذي يحمله Codex محليًا.

سبب استبدال الآلية السابقة: تطبيق سطح المكتب يشغّل app-server عبر stdio، ولا يوفر مقبس daemon الذي افترضه الموصل. `proxy` فشل بخطأ Windows 10050، و`exec resume` تعارض مع كاتب جلسة سطح المكتب. لا نعيد تشغيل التطبيق أو نكسر أقفال المحادثات.

## التفويض والحماية

صفحة `/sessions/jobs/` للمشرف فقط. يحفظ الطلب نسخة سياسة النموذج والتفكير، وصلاحية القراءة أو تعديل المشروع. مفتاح إرسال فريد يمنع تكرار POST. لا يوجد تصعيد لنموذج أقوى أو إعادة تلقائية. تعمل الطلبات بالتتابع، ويمنع قيد قاعدة البيانات أي تنفيذ تالٍ أثناء `running` أو `uncertain`.

الصلاحيات الإضافية لا تمنح آليًا (`approvalPolicy=never` مع قراءة فقط أو كتابة داخل المشروع). عند المهلة يوقف الموصل شجرة العملية التابعة له على Windows ويحتفظ بحالة غموض للمراجعة، دون ادعاء التراجع عن التغييرات التي وقعت. لا يعاد الطلب الغامض تلقائيًا.

## الأدلة والمراقبة

يحفظ معرف جلسة التنفيذ فور وصوله، ويربطه بجرد الاستهلاك. يسجل الرد النهائي واستهلاك الدور كما أرسله CLI، ويتحقق من النموذج من `turn_context` للجلسة نفسها. المخزن مؤقتًا جزء من الإدخال؛ لا تجمعه إليه ثانية. لا ينقل سجلات الأدوات الكاملة إلى قاعدة البيانات.

المراقب: `python backend/manage.py run_model_dispatcher --watch`. يعرض الموقع نبض الاتصال وحالة التنفيذ. تشغيله محلي؛ يبدأ عند تسجيل دخول المستخدم إلى Windows بواسطة المهمة المجدولة ShadowDanger-ModelDispatcher، ولا يعمل عبر Railway دون موصل محلي مستقل.

## بدء Windows ومنع التكرار

المثبت القابل للتكرار: `tools/install-dispatcher-startup.ps1`. يسجل مهمة عند تسجيل الدخول تحت هوية المستخدم الحالية بصلاحية Limited وInteractive؛ لا يحفظ كلمة مرور ولا يعمل بحساب SYSTEM. التشغيل الخفي بواسطة pythonw و`tools/run-dispatcher.py`، والمخرجات في `backend/.local/dispatcher-startup.log`. الإعداد IgnoreNew يمنع نسختين من المهمة المجدولة، وقفل ملف على مستوى نظام التشغيل يمنع النسخ اليدوية أيضًا ويتحرر تلقائيًا عند انتهاء العملية. لا تحذف ملف القفل أثناء العمل.

يحاول Windows إعادة المراقب بعد الفشل ثلاث مرات بفاصل دقيقة؛ هذا يعيد المراقب فقط، ولا يعيد إرسال مهام النموذج. عند الاستعادة، يتحول الطلب الذي بقي running إلى uncertain للمراجعة. يحتفظ DispatcherRun بتاريخ البدء والتوقف والانقطاع، وDispatcherHeartbeat بآخر نبض كل خمس ثوان حتى أثناء تنفيذ مهمة، ورقم العملية وطريقة بدء التشغيل وآخر خطأ عام. يعتبر العرض نبضًا أقدم من 20 ثانية غير متصل.

جلسة «ظل الخطر — التنسيق العام» موجودة ضمن التفويض؛ سياسة تنفيذها الافتراضية gpt-6-luna / low. لا يعني ذلك تغيير نموذج محادثة التنسيق المفتوحة، ولا وراثة تاريخها. ينشئ الأمر configure_local_dispatcher ميثاقها مرة واحدة ويحافظ على التعديلات اللاحقة.

التحقق الإضافي: 57 اختبارًا ناجحًا. شُغّلت المهمة من Windows Task Scheduler وظهرت Running مع نبض فعلي. رُفض تشغيل يدوي ثانٍ دون إنشاء سجل تشغيل جديد. اختبر تحرير القفل، توثيق التوقف، فشل قاعدة البيانات، والعثور على Codex عندما لا يحتوي PATH على مساره. لم تُعد إعادة تشغيل الجهاز نفسه أثناء الاختبار. إيقاف المراقب أو إزالته يتم من Task Scheduler باسم المهمة أعلاه؛ تبقى السجلات محفوظة.
