# موصل تشغيل النماذج المحلي

## الآلية المعتمدة محليًا

يستخدم الموصل `codex exec` لإنشاء تنفيذ مستقل لكل طلب، بالنموذج والتفكير المحددين في السياسة. يرتبط التنفيذ بميثاق الجلسة في قاعدة البيانات وبسجل استهلاك التوكنز. لا يستأنف محادثة سطح المكتب ولا يغير نموذجها ولا يرث تاريخها؛ يرسل نطاق الجلسة وميثاقها والمهمة المحددة فقط، إضافة إلى السياق الذي يحمله Codex محليًا.

سبب استبدال الآلية السابقة: تطبيق سطح المكتب يشغّل app-server عبر stdio، ولا يوفر مقبس daemon الذي افترضه الموصل. `proxy` فشل بخطأ Windows 10050، و`exec resume` تعارض مع كاتب جلسة سطح المكتب. لا نعيد تشغيل التطبيق أو نكسر أقفال المحادثات.

## التفويض والحماية

صفحة `/sessions/jobs/` للمشرف فقط. يحفظ الطلب نسخة سياسة النموذج والتفكير، وصلاحية القراءة أو تعديل المشروع. مفتاح إرسال فريد يمنع تكرار POST. لا يوجد تصعيد لنموذج أقوى أو إعادة تلقائية. تعمل الطلبات بالتتابع، ويمنع قيد قاعدة البيانات أي تنفيذ تالٍ أثناء `running` أو `uncertain`.

الصلاحيات الإضافية لا تمنح آليًا (`approvalPolicy=never` مع قراءة فقط أو كتابة داخل المشروع). عند المهلة يوقف الموصل شجرة العملية التابعة له على Windows ويحتفظ بحالة غموض للمراجعة، دون ادعاء التراجع عن التغييرات التي وقعت. لا يعاد الطلب الغامض تلقائيًا.

## الأدلة والمراقبة

يحفظ معرف جلسة التنفيذ فور وصوله، ويربطه بجرد الاستهلاك. يسجل الرد النهائي واستهلاك الدور كما أرسله CLI، ويتحقق من النموذج من `turn_context` للجلسة نفسها. المخزن مؤقتًا جزء من الإدخال؛ لا تجمعه إليه ثانية. لا ينقل سجلات الأدوات الكاملة إلى قاعدة البيانات.

المراقب: `python backend/manage.py run_model_dispatcher --watch`. يعرض الموقع نبض الاتصال وحالة التنفيذ. تشغيله محلي؛ ليس خدمة تبدأ تلقائيًا بعد إعادة تشغيل Windows، ولا يعمل عبر Railway دون موصل محلي مستقل.
