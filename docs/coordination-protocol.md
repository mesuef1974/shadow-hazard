# بروتوكول التنسيق بين الشات وClaude Code (مختصر للوكلاء)

> النسخة الكاملة للبشر: صفحة «بروتوكول التنسيق» في Project «مسابقة علوم المستقبل 6». هذا الملف هو ما يقرأه الوكيل.

- الذاكرة المشتركة: `docs/handoff-2026-11-04.md`. كل سطح يقرأه أولًا ويكتب فيه آخرًا. يبقى تحت 60 سطرًا.
- الشات: قرارات، وثائق، بحث، أوامر مهام، مراجعة نتائج. لا يعدّل الكود ولا يقرأه كاملًا.
- Claude Code: كود، اختبارات، محاكي، عتاد لاحقًا. لا قرارات ولا مناطق مجمّدة. جلسات الكود محلية في مجلد المشروع لتُقاس وتعمل الحرّاس.
- أمر المهمة: `docs/tasks/NNNN-<slug>.md`، عشرة أسطر: الهدف، الملفات، القبول، خارج النطاق، المرجع، الإنهاء.
- جلسة Claude Code = مهمة واحدة. يقرأ أمر المهمة وملف التسليم فقط. ينفّذ بـ`minimal-code-edit` ويختبر بـ`focused-testing`.
- الإنهاء: ثلاثة أسطر تحت «حالة الكود» في ملف التسليم (ما تغيّر، الاختبارات، التالي).
- سطح واحد على `src/` و`backend/simulation/` في أي وقت. Codex متوقف منذ 2026-11-04 ([ADR 0002](decisions/0002-occlusion-aware-core.md)).
- كسر البروتوكول لإصلاح عطل فقط، مع سطر في ملف التسليم.
- الأتمتة والحرّاس (حارس التجميد، فحص ما قبل الدفع، SessionStart، CI، الخلاصات، سطر الكلفة) مرجعها الوحيد [ADR 0003](decisions/0003-automation-layers.md) منذ 2026-11-04. القرار النافذ يصير حارسًا أو اختبارًا لا فقرة تُقرأ. القراءة الطويلة في وكيل فرعي. النموذج الأخف للروتين والأعلى للحكم. تفعيل الحرّاس مرة لكل نسخة: `python scripts/install_hooks.py`.
